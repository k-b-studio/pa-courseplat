# Decisions log (append-only)

Decisions the specs leave open, with the reason. Format: date · spec · decision · reason.

- **2026-11-19 · 02 · SvelteKit 2.70 with `@sveltejs/adapter-vercel` 6, TypeScript 6, Vitest 4.** npm's latest Kit is 3.x, but spec 02 fixes SvelteKit 2; adapter-vercel 7 requires Kit 3, and Kit 2's peer range stops at TypeScript 6.
- **2026-11-19 · 02 · ThaiLLM stays on HTTPS.** A one-request probe to `https://thaillm.or.th/api/v1/chat/completions` returned HTTP 200, so the `http://` examples in `thaillm-api.md` are not needed.
- **2026-11-19 · 02 · ThaiLLM `response_format`.** The endpoint accepts `{type:"json_schema", json_schema:{…, strict:true}}` and `{type:"json_object"}` (probed with `typhoon`). The client still falls back json_schema → json_object → plain instructions on HTTP 400 and remembers what worked. `pathumma` writes its `<think>…</think>` block inline in `content` (not in `reasoning_content`), so replies are always stripped before parsing.
- **2026-11-19 · 02 · Local database tests use PGlite, not `supabase start`.** No Docker on the dev machine. `tests/support/supabase-shim.sql` stands in for the Supabase roles, `auth.uid()/jwt()/users` and `storage.*`; the real migrations, functions and RLS run on PGlite in `npm run test`. The shared project receives a phase's migrations only after these pass, and only after the creditGPAX snapshot.
- **2026-11-19 · 02 · Rule 5 wins over the SQL listing.** `extractions.created_by`, `caution_comments.author_id` and `course_notes.author_id` are nullable with `on delete set null` (the SQL block shows `not null`; rule 5 and AC 9 require deletion to succeed).
- **2026-11-19 · 02/04/05 · Students read the published snapshot; the working document is private.** `offerings.syllabus` is the instructors' working draft. Student pages render `offering_versions` at `published_revision`. Column privileges hide `offerings.syllabus` from plain selects; editors and staff read it through `get_offering_syllabi()` (which checks `can_edit_offering`). Reason: with autosave, a live column would push unpublished edits and accepted AI imports on an already-published offering straight to students, contradicting spec 05 R17. Editing a published offering shows "มีการแก้ไขที่ยังไม่เผยแพร่" and Publish re-snapshots.
- **2026-11-19 · 02/06 · Reading key is composite.** `syllabus_items.norm_key` is `isbn:…|doi:…|t:<norm_title>` (missing parts omitted); Stage 1 matches when any part is shared. With `coalesce(isbn, doi, title)` the 2404324 Dye (has an ISBN) and the 2404429 Dye (no ISBN) would never match, and spec 06 AC 4 requires that caution every time.
- **2026-11-19 · 02/06/07 · Small additions to the data model.** `caution_events` (resolution history shown in the caution drawer), `course_visits` (spec 07 R12: highlight handover notes added since the last visit), `caution_runs.trigger` also allows `import` (runs after accepting an AI import, spec 06 R4). `section_instructors.pending_email`, `profiles.cautions_seen_at` and the one-active / one-upcoming partial unique indexes are in `0001_schema.sql` rather than later migrations, since nothing had been applied yet.
- **2026-11-19 · 03 · Sign-up hook is not `security definer`.** Supabase's hook docs recommend against it; the hook reads `courseplat.demo_accounts` through a grant and an RLS policy for `supabase_auth_admin`. The refusal message keeps the word "PolSci", which creditGPAX's return page checks.
- **2026-11-19 · 03 · `ensure_profile()` decides the role from the address, whatever the provider.** The hook already limits email-provider sign-ups to `demo_accounts`, so the provider adds no safety here, and spec 03 AC 7 needs an Admin-API-created PolSci user to become a student. Order: staff directory → demo account → student pattern → `@chula.ac.th` viewer.
- **2026-11-19 · 02/03 · `can_edit_offering()` also requires role instructor or staff.** Removing someone from the directory (→ viewer) removes their edit rights even while they are still listed on a section.
- **2026-11-19 · 02 · `npm run db:migrate` refuses a non-local database until `.snapshots/public-before.json` exists**, so the creditGPAX snapshot (spec 02 AC 1) cannot be skipped.
- **2026-11-19 · 03 · Sessions are validated with `auth.getUser()`** as spec 03 says (Supabase's page now also offers `getClaims()`; `getUser()` is the stricter, documented choice in the spec).
